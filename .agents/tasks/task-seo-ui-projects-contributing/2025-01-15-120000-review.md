# SEO, UI polish, expanded project catalog, and CONTRIBUTING.md

This change turns a minimal 6-project bilingual directory into a richer 18-project catalog while layering on SEO infrastructure (per-page metadata, Open Graph, sitemap, robots.txt, JSON-LD, canonical URLs, hreflang alternates), visual improvements (dark mode, entrance animations, search/filter, breadcrumbs, color-coded scores, deploy badges, scroll-to-top), and a comprehensive contributor guide. The approach is conservative: all additions are static-site compatible, the CSS is vanilla (no framework), and the data model stays unchanged.

**Watch for:** The root `<html lang="vi">` is hardcoded for all pages including English, contradicting the hreflang and locale metadata (confirmed). Deploy snippets ship hardcoded placeholder passwords that users will likely copy verbatim (confirmed). The sitemap `lastModified` is a static date that will silently become stale (confirmed).

## High-level view

The SEO layer adds `generateMetadata` exports to every page route, emitting Open Graph, canonical URLs, and hreflang alternates. A `sitemap.ts` and `robots.ts` provide crawler entry points. JSON-LD structured data (WebSite + ItemList) is injected on the homepage. A cross-cutting issue undermines the effort: the root layout sets `<html lang="vi">` unconditionally, so English pages are served with the wrong document language.

The UI additions are CSS-only dark mode, entrance animations with a `prefers-reduced-motion` escape hatch, and small interactive components (search, scroll-to-top). The `SearchFilter` client component receives the full project array as props — including multi-line Docker Compose strings — which inflates the page payload unnecessarily.

The project data expansion triples the catalog from 6 to 18 entries. Deploy snippets contain hardcoded passwords with inconsistent signaling: some say `change-me`, others use `immich_password` or `admin` with no indication they must be replaced.

## Hardcoded document language vs. locale routing

The root layout at `app/layout.tsx` renders `<html lang="vi">` unconditionally. The locale-level layout (`app/[locale]/layout.tsx`) wraps children in `SiteShell` but never touches the `<html>` element. Meanwhile, every page's `generateMetadata` emits `locale: "vi_VN" | "en_US"` in Open Graph and builds hreflang alternates for both languages. Search engines see a page declaring itself English in meta but Vietnamese at the document level — this mismatch degrades crawl signals for the English variant.

The fix is to move the `<html>` rendering into the locale layout (making it a root-replacing layout) or pass `lang` dynamically from the route params.

## Deploy snippet credential hygiene

The 18 project entries contain Docker Compose YAML and setup scripts rendered as copyable code blocks. The credential patterns are inconsistent:

- Authentik, Outline, Langfuse: use `change-me-*` prefixes — clear signal to replace.
- Immich: `immich_password` — looks like a configured value, not a placeholder.
- Grafana: `GF_SECURITY_ADMIN_PASSWORD: "admin"` — the deploy guide mentions changing it, but the snippet itself doesn't flag it.
- NocoDB, n8n, Metabase, Nextcloud: `{name}_password` — ambiguous whether it's final.

Users copying these snippets (the entire point of the copy-to-clipboard UI) may deploy services with predictable credentials. A consistent approach: use an obvious marker like `CHANGEME_<purpose>` and add a YAML comment `# CHANGE THIS` on the same line.

## SearchFilter client boundary and data serialization

`SearchFilter` is a `"use client"` component receiving the full `projects` array as a prop. Each project includes `deploySnippets.dockerCompose` and `deploySnippets.setupScript` — multi-line strings that can be hundreds of bytes each. The component only reads `name`, `tags`, `slug`, `summary` and renders `ProjectCard` (which itself only uses `name`, `slug`, `category`, `score`, `tags`, `deploy`, `summary`, `iconUrl`). Passing a projection of just these fields would eliminate the compose/script strings from the client bundle.

## Sitemap freshness

```typescript
const lastModified = new Date("2025-06-01");
```

Every sitemap entry claims the same modification time regardless of when content was added. After a deploy that adds new projects, the sitemap still reports June 2025. Using `new Date()` at build time would at least reflect the deployment date.

## Footer GitHub link placeholder

In `site-shell.tsx`, the footer links to `https://github.com` rather than the project's repository:

```tsx
<a href="https://github.com" target="_blank" rel="noreferrer">
  GitHub
</a>
```

This should point to the actual selfhost-directory repository.
